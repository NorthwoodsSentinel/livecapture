# AGENTS.md — livecapture

Rules for any agent (or person) changing this repo. The shape and most of the wording come from the
`modelcontextprotocol/inspector` AGENTS.md (branch v2/main, commit d330df9617e44ec893bc1a53618662239342d433), as the
maintainer ruled on it on 2026-11-14. Where the upstream way and ours differ, **the source's way stands until there is a
reason to depart**; every departure below says why.

`CLAUDE.md` contains only `@./AGENTS.md`. Keep one copy of these rules: two copies are strictly worse than one,
because the stale copy is indistinguishable from the live one.

## What this is

A Cloudflare Worker (R2 + D1 + KV + Workers AI) that receives live audio chunks from a capture client, stores the
raw audio in R2, transcribes it (Workers AI Whisper, or a local Whisper runner for sessions marked `local-only`),
writes transcript segments to D1, and serves a read API over them. `README.md` describes the design and the API;
`docs/local-whisper-pipeline.md` describes the local runner contract; `tools/` holds a file-replay script and a
Windows capture client.

## The invariants (read this before touching `src/`)

- **Two bearer gates.** `/ingest`, `/sessions/:id/end` and `/read/*` require `INGEST_TOKEN`; `/local-pickup/*`
  requires the separate `LOCAL_PICKUP_TOKEN` so the local runner's credential can be revoked on its own. Each
  answers 503 when its secret is unset and 401 on a missing or wrong token. Only `/health` is open: it matches the path
  for any method, and it has no side effects. **Never weaken a gate**: no new open route, no fallback comparison, no route matched before the
  gate. Changing one is a decision made explicitly in the issue; a refactor, a lint fix or a review suggestion is
  never a reason.
- **`local-only` audio never reaches Workers AI.** Engine selection follows the session's
  `transcription_preference`, not its sensitivity tier. `/ingest` dispatches on it, and `transcribeChunk` refuses a
  `local-only` session again as defense in depth. Both are asserted in `test/`; keep both.
- **Ingest is idempotent on `(session_id, sequence)`.** A repeated chunk returns the existing `chunk_id` and is
  never stored or transcribed twice.
- **Read endpoints filter likely Whisper hallucinations by default** (`include_hallucinations=true` or `1` turns it
  off). Non-English text alone is never treated as a hallucination.
- Repairs are recorded in `KINTSUGI.md` (append-only), with a `kintsugi:` comment at the site, as that file
  describes.

## Project structure

- `src/index.ts` — the fetch entry, routing, and mapping of errors to responses.
- `src/ingest.ts` — `/ingest` and session end. `src/read.ts` — the read API. `src/local-pickup.ts` — the local
  runner API. `src/transcribe.ts` — the Workers AI path.
- `src/lib.ts` — auth, ids, R2 keys, D1 queries, the hallucination filter, the KV pointer, engine policy.
- `src/types.ts` — the data model and `Env`.
- `migrations/` — D1 schema. `wrangler.toml` — bindings. `worker-configuration.d.ts` — generated by
  `wrangler types`; read by the typechecker only.
- `test/` — Vitest suites (`*.test.ts`) and `test/helpers/fakes.ts` (in-memory D1, KV, R2 and Workers AI).
- `scripts/` — gate tooling. `tools/` — operator scripts, not deployed.

## Development setup

- `bun install`. Bun runs this repo's own scripts (`bun run <script>`); if you run one of the upstream project's own tools
  or procedures, use its runner (`npx`) as it documents.
- Tests run on Vitest with `@vitest/coverage-v8`, the upstream choice, because Bun's coverage cannot measure branches
  or enforce a per-file bar.
- No Cloudflare account, secret or network is needed for any gate step. Tests use in-memory fakes; nothing
  reaches Cloudflare.

## Issue-driven work style

Linear is the board. The rules:

- **Before starting work, find the issue.** Every change has one. Before filing a new one, search for a match:
  **never create a duplicate**.
- **`Todo` means the maintainer approved it, and only the maintainer moves an issue into `Todo`.** `Backlog` is
  filed, not approved. Start work only on an approved issue.
- **Label by type: exactly one of `bug` / `enhancement` / `documentation` / `chore` / `question`.** Work run through
  this process also carries the factory label (not named yet; until it is, say "factory method" in the PR).
- **`Done` means the work shipped** (its PR merged) and was verified. Anything else is canceled, not done.
- **When work begins**, assign yourself, set the issue In Progress, and create the branch **in a new git worktree**,
  never by switching branches in a checkout another session may share.
- **When work is complete**, run `bun run format` then `bun run local:gate`, **sign off every commit**
  (`git commit -s`), open a PR with **the issue reference as the body's first line**, and set the issue In Review.
- **After opening a PR, run a Codex review loop** (`codex exec --sandbox read-only`), unprompted. Stop on the
  **first** clean round (no confirming round "just to be sure"). **Weigh each finding against the issue the PR
  closes and decline scope expansion.** Two failed rounds in a row: stop, leave the PR open, list the findings in
  it. (Departure: the upstream uses Copilot; the maintainer chose Codex as the off-lineage reviewer.)
- **If new tasks are discovered during development, file issues** rather than widening the PR.
- **Pace bulk GitHub writes: 1 s between requests, never in parallel**, under 80 a minute and 500 an hour.
- **A security issue stays private until its fix is ready**; accepting or publishing an advisory is outward-facing
  and stays human-gated, never automated.
- **This repo is public. Merging is the maintainer's act**, and nothing personal goes into a commit, PR or test
  (home paths, emails, names, tokens, recordings). Tests use synthetic data only.
- **Deploys are human-gated.** `bun run deploy` and the `d1:*`, `kv:*`, `r2:*` scripts act on a live Cloudflare
  account and are run by whoever operates an instance. No agent runs them, and no workflow deploys.

### Responding to code reviews

- Judge each suggestion against the issue the PR closes. Fix defects in what the PR added; decline, with a reason,
  what expands it; file an issue for anything worth doing on its own.
- Reply in each review comment's own thread (a rollup comment does not discharge it), then post a summary in
  addition.

## Always test new or modified code

- **Ensure all code has corresponding tests. Every measured file must clear ≥ 90 on all four dimensions (lines,
  statements, functions, branches), per file**, enforced by `vitest.config.ts` and therefore by `bun run test`,
  `bun run local:gate` and CI. This is the source's bar (the upstream inspector). **Never lower the threshold to pass.**
- Measured scope: `src/**/*.ts` and `tools/**/*.ts`. Measured on 2026-11-16 (statements / branches / functions /
  lines): `src/index.ts`, `src/ingest.ts`, `src/read.ts`, `src/transcribe.ts` 100 / 100 / 100 / 100;
  `src/lib.ts` 99.15 / 98.87 / 100 / 100; `src/local-pickup.ts` 100 / 100 / 100 / 100. `src/types.ts` holds types
  only and has nothing executable to measure.
- **Coverage exclusions are exact paths, one per entry, each with a reason and a follow-up issue; never a glob**
  that could hide a new file. Current list (in `vitest.config.ts`): `tools/replay-file.ts`, a command-line script
  that runs on import, shells out to ffmpeg and posts to a live deployment; testing it needs its helpers split
  out first.
- **A genuinely-unreachable branch is annotated at the source** (`/* v8 ignore next -- <reason> */`), never waved
  through by lowering the gate.
- **A gate must show how much it checked.** `scripts/verify-gate-scope.ts` runs after the tests and fails if a
  tracked `.ts` file is outside the tsconfig project, a measured source file is missing from the coverage summary,
  or a coverage exclusion is a glob or names no tracked file. Fix that by fixing the globs, never by excusing the
  file.
- Test files are `test/**/*.test.ts`; a file named otherwise is silently not run.
- A test that races is fixed with fake timers or an awaited condition, never with a longer timeout.

## Mandatory pre-push gate

- **ALWAYS run `bun run format` before committing.**
- **`bun run local:gate` is the mandatory pre-push command.** It runs every check CI runs: `format:check`,
  `lint`, `typecheck` and `test` (Vitest with the coverage bar, then the gate-scope check). A green run here means
  every check CI applies has already passed on your machine.
- There is deliberately no `ci` script (the name collides with the package-manager built-in). CI runs the four
  stages directly and never calls a `local:*` script.
- Departures, each for a stated reason: no gate lease (the gate takes seconds and binds no ports); no DCO check
  job (adding the required-check ruleset is a repository setting, the maintainer's to change); no smoke stage
  (there is no built artifact to drive without a Cloudflare account).

## Waiting on long-running work

**When you are waiting for something to finish, arm a notifier and stop. Never spend turns polling.** For state
the harness cannot observe (a CI run, a remote review), poll inside one backgrounded loop that exits when the
condition holds, at 30 s or more. **If a notifier is already armed, that settles it: wait.**

## Build output is never a gate target

**No gate (lint, format or typecheck) may read generated output.** Out of scope: `node_modules/`, `.wrangler/`,
`coverage/`, `dist/`, `bun.lock`, and lint and format skip the generated `worker-configuration.d.ts`. Each scope
states it: `globalIgnores` in `eslint.config.js`, `.prettierignore`, and the tsconfig `include` list that names
source directories (it matters here: `allowJs` is on, so a bare default would typecheck `coverage/`). **When a
build starts writing to a new location, add it to the ignore lists in the same change.** Never widen an ignore to
silence a finding in first-party code. Markdown is also outside the format scope: prettier rewrites prose.

## Lint has no warning tier

**`lint` runs with `--max-warnings 0`, so a warning fails the gate exactly as an error does.** Rules: ESLint
recommended, typescript-eslint recommended, and `@typescript-eslint/no-floating-promises` at `error`.

- **Do not silence a finding to satisfy the gate.** A warning is a defect to fix. If a rule genuinely must be
  waived on one line, use its inline disable comment **with a one-line justification**. Dropping a rule or
  widening an ignore to make `lint` pass is not a fix.
- Prefer `error` for any rule you intend to enforce.

## TypeScript

- TypeScript for all code. Never `any`: type D1 rows, narrow JSON at the boundary from `unknown`.
- No floating promises: `await` them, or `void` them with a comment saying why.
- Every new file starts with a header comment saying what it is for and why.
- A rule about what the code does is asserted at runtime in a test, not read out of the source.
